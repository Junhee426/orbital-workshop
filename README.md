# 궤도 정비소 · Orbital Workshop v0.1

작업선을 몰고 기상위성에 접근해 고장을 진단하고 태양전지판을 복구하는 **싱글플레이 3D 브라우저 시제품**입니다.

![게임 시작 화면](docs/images/01-home.png)

## 가장 간단한 실행

ZIP을 풀고 **`PLAY.html`을 데스크톱 Chrome·Edge·Firefox 등 WebGL 2 지원 브라우저로 열면 바로 플레이할 수 있습니다.** 이 파일에는 게임 코드, 3D 엔진과 글꼴이 모두 들어 있습니다. Python이나 npm 설치 없이 실행됩니다.

직접 파일 실행은 Chromium에서 확인했습니다. 다른 브라우저에서 로컬 파일 실행이 제한되거나 소스를 수정해 개발할 때는 아래 Python 실행 방법을 사용하세요.

## 소스 실행·개발

Python 3.10 이상과 WebGL 2를 지원하는 데스크톱 브라우저가 필요합니다. 게임 실행에 npm·pip 설치는 필요하지 않습니다. 렌더링 엔진과 한글 글꼴을 포함하므로 실행 중 외부 CDN을 사용하지 않습니다.

1. ZIP을 풀고 `orbital-workshop` 폴더를 엽니다.
2. 터미널에서 아래 명령을 실행합니다.
3. 브라우저에서 **http://127.0.0.1:8000** 을 엽니다.

```bash
python server.py
```

macOS·Linux에서 `python` 명령이 없다면 `python3 server.py`를 사용하세요. Windows에서는 `start_windows.bat`를 실행할 수 있고, macOS·Linux에서는 `sh start_mac_linux.sh`를 사용할 수 있습니다. 서버가 실행된 터미널을 열어둔 채 플레이합니다.

`index.html`을 직접 더블클릭하면 브라우저의 모듈 로딩 제한 때문에 실행되지 않을 수 있습니다. 반드시 위 주소로 접속하세요. 8000번 포트가 사용 중이면 `python server.py --port 8010`으로 실행하고 주소의 포트도 바꿉니다.

## 이번 버전에서 할 수 있는 것

- 작업선 1대와 기상위성 1종을 이용한 첫 임무 완주
- 관성 이동, 추진제 사용, 제동, 미세 추력, 자동 자세 보조와 수동 방향 조절
- 거리·상대속도·방향·회전 차이를 확인하는 포획 판정
- 전원부와 전개부 스캔, 증거를 비교하는 고장 진단
- 전원 분리 → 로봇팔 고정 → 토크 조절·래치 해제 → 전원 연결 → 전개 시험
- 패널 전개 애니메이션, 발전 상태·통신 신호 복구, 관측팀 메시지
- 의뢰 보상, 정비소 귀환, 실제 조종에 적용되는 정밀 추진기 업그레이드
- 같은 수리 임무에 회전을 더한 정비 훈련
- 자동 저장·이어하기, 일시정지, 접근 재시도, 저사양 모드, 효과음, 모바일 보조 조작

## 조작

| 입력 | 동작 |
|---|---|
| W / S | 전진 / 후진 추력 |
| A / D | 좌우 추력 |
| Q / E | 하강 / 상승 추력 |
| Space | 제동 |
| Shift + 이동키 | 미세 추력 |
| 방향키 | 수동 방향 조절. 수동 입력 시 자세 보조가 꺼집니다. |
| T | 대상의 방향을 따라가는 자세 보조 켜기·끄기 |
| F | 포획·검사·정비 실행. 래치 작업 중에는 길게 누릅니다. |
| R | 접근 지점으로 견인. 수리 중에는 적용되지 않습니다. |
| 마우스 드래그 / 휠 | 카메라 회전 / 확대·축소 |
| Esc | 일시정지 |
| H | 조작 안내 |

화면 속 부품 표식을 클릭하면 작업 부위를 선택할 수 있습니다. 모든 주요 작업은 화면 버튼으로도 실행 가능합니다. 모바일 화면에는 이동·제동 버튼을 제공합니다. 모바일 화면 검사는 Chromium의 터치 화면 에뮬레이션으로 수행하며 실제 iPhone·Android 기기의 성능 확인은 별도입니다.

## 첫 임무 진행 안내

1. **작업 시작:** W를 짧게 눌러 접근합니다. 키를 놓아도 관성으로 계속 이동합니다.
2. **제동과 보정:** 목표에 가까워지기 전에 Space로 감속하고 A/D, Q/E로 결합부 정면에 맞춥니다. 필요하면 Shift로 미세 조정합니다.
3. **포획:** 오른쪽 거리·속도·방향 표시를 확인합니다. 거리 1.15m 미만, 접촉점 상대속도 0.48m/s 미만, 방향 오차 14° 미만, 회전 차이 0.14rad/s 미만에서 F를 누릅니다. 수치는 게임용 허용 범위입니다.
4. **진단:** 전원부와 전개부 표식을 각각 선택해 스캔합니다. 전압과 명령 수신은 정상인데 패널 위치가 바뀌지 않는 것을 확인합니다. 원인으로 ‘전개부 래치 고착’을 선택합니다.
5. **전원 분리·고정:** 전원부를 선택해 구동 전원을 분리한 뒤 고정점을 선택해 작업 팔을 연결합니다.
6. **래치 해제:** 래치 표식을 선택하고 오른쪽 토크 슬라이더를 40–60%로 맞춥니다. F 또는 작업 버튼을 약 3초 동안 누릅니다. 이 구간은 물리적 실측 토크가 아닌 게임 게이지입니다.
7. **작동 시험:** 전원부를 다시 연결하고 전개 시험을 시작합니다. 패널 전개와 신호 회복을 지켜봅니다.
8. **정비소 귀환:** 보상으로 정밀 추진기를 구입하거나 회전 표적 훈련을 시작할 수 있습니다. 업그레이드는 다음 출항부터 적용됩니다.

처음 의뢰에는 제한시간이 없습니다. 잘못 진단해도 다시 선택할 수 있습니다. 충돌은 선체 상태와 보상에 영향을 주지만 첫 임무를 즉시 종료하지 않습니다. 대상에서 멀어지거나 추진제가 부족하면 R로 다시 접근할 수 있습니다.

## 저장

- 진행 상태와 정비소 정보는 현재 브라우저·주소의 로컬 저장소에 저장됩니다. `PLAY.html`과 서버 실행 주소는 서로 다른 저장 공간을 사용할 수 있습니다.
- 임무 단계 변경과 약 2.5초 간격으로 저장합니다. 다른 탭으로 이동하면 작업이 일시정지됩니다.
- 도중에 창을 닫았다면 ‘저장된 작업 이어하기’를 선택합니다. 진행 중이던 스캔·시험은 재실행하고, 완료한 정비 단계와 래치 해제 진행률은 유지합니다.
- 시크릿 모드 종료, 브라우저 데이터 삭제, 다른 주소로 접속하면 저장 자료가 이어지지 않을 수 있습니다.
- 일시정지 메뉴의 ‘진행 파일 다운로드’는 지원·개발용 JSON 백업입니다. v0.1에는 백업 파일을 불러오는 화면이 없습니다.

## Render 배포

이 패키지에는 `render.yaml`을 포함했습니다. **실제 배포나 GitHub 저장소 생성은 수행하지 않은 상태**입니다.

1. 이 폴더의 내용이 저장소 루트가 되도록 GitHub에 올립니다.
2. Render에서 해당 저장소를 연결하고 Blueprint를 생성합니다.
3. 이름·플랜을 검토한 뒤 배포합니다. 구성에는 Python Web Service와 free 플랜, Singapore 리전이 지정되어 있습니다.

수동 Web Service 생성 시 사용할 값은 다음과 같습니다.

| 항목 | 값 |
|---|---|
| Runtime | Python |
| Build Command | `python -m compileall -q server.py` |
| Start Command | `python server.py --host 0.0.0.0` |
| Health Check Path | `/healthz` |

포트는 Render의 `PORT` 환경변수에서 읽습니다. 서버는 시제품용 정적 파일 서버이며, 게임 진행은 사용자 브라우저에서 계산·저장합니다. `web` 폴더만 별도의 정적 호스팅에 올리는 방식도 가능합니다.

## 개발용 테스트

Node.js 20 이상에서 로직 테스트를 실행할 수 있습니다.

```bash
npm test
```

선택적으로 브라우저 통합 테스트를 실행하려면 개발용 Playwright와 Chromium을 설치합니다. 게임 실행 자체에는 필요하지 않습니다.

```bash
npm install --no-save playwright
npx playwright install chromium
node tests/e2e.mjs
```

테스트가 Python 서버를 직접 시작하고 종료합니다. Windows에서 Python 명령이 `python`인 경우 `PYTHON=python` 환경변수를 지정하세요. `PLAYWRIGHT_MODULE`, `ORBITAL_CHROMIUM_EXECUTABLE`, `ORBITAL_TEST_PORT`, `ORBITAL_SCREENSHOT_DIR`로 테스트 환경을 지정할 수 있습니다.

소스를 변경한 뒤 `PLAY.html`을 다시 만들려면 개발용 번들러를 설치하고 빌드합니다.

```bash
npm install --no-save esbuild@0.25.10
node tools/build_standalone.mjs
```

## 범위

v0.1은 **첫 임무와 얕은 정비소 성장**을 구현한 시제품입니다. 3종의 위성·5개의 서로 다른 임무, 견인 임무, 자유로운 부품 교체, 다중 고장, 협동 플레이는 후속 개발 범위입니다.

근접 운동은 국소 좌표계의 단순화한 모델입니다. 전체 궤도역학, 정밀 충돌·접촉 해석, 실제 고장 진단을 재현하지 않습니다. 지구풍 배경도 절차적 시각 연출이며 실제 지형 자료가 아닙니다.
