# 구현 범위와 후속 개발

## v0.1에서 확정한 선택

- 플랫폼: PC 브라우저 우선. 모바일은 반응형 UI와 보조 입력을 제공한다.
- 그래픽: Three.js 0.180.0. 라이브러리와 글꼴을 로컬 파일로 포함한다.
- 서버: Python 표준 라이브러리. 게임 데이터는 브라우저에서 처리한다.
- 임무: 기상위성 전개부 래치 고착 한 가지. 동일 고장의 회전 표적 훈련을 추가한다.
- 시점: 3인칭 접근, 결합 후 근접 작업 카메라. 사용자가 회전·확대 가능하다.
- 진행: 증거 확인, 원인 선택, 작업 순서, 기능 복구를 상태 기계로 연결한다.
- 성장: 400 CR 기본 보수와 최대 100 CR의 작업 보너스. 접촉·견인 시 보너스가 감소한다. 정밀 추진기 비용은 180 CR이다. 모두 게임 밸런스 초깃값이다.

## 설계와의 대응

| 설계의 요소 | 구현 | 현재 경계 |
|---|---|---|
| 관성·상대운동 | 추력, 자유 활주, 제동, 회전 표적 | 완전한 강체 동역학·궤도 전파가 아님 |
| 조건부 포획 | 거리·접촉점 속도·방향·회전 차이 판정 | 결합 후 운동은 감쇠·보간으로 단순화 |
| 단서 기반 진단 | 전원·전개부 두 검사와 원인 선택 | 첫 고장만 수작업으로 구성 |
| 공간적 정비 | 3D 부품 표식 선택, 로봇팔 고정, 래치 이동 | 부품 선택은 화면 표식으로 보조하며 정밀 수동 로봇팔은 후속 |
| 작업의 결과 | 패널 전개, 전력·신호 정상화, 고객 메시지 | 고객 대사는 텍스트 무전 형식 |
| 장비 성장 | 추력을 세밀하게 하고 제동력을 높이는 업그레이드 | 장비 한 종류 |
| 장기 운영 | 반복 의뢰 보상, 회전 표적 훈련 | 전체 서비스 지도·고객별 시나리오는 후속 |

## 상태 전이

접근 후 포획 조건을 충족해야 상태 스캔으로 이동한다. 전원부·전개부 검사 결과를 모두 얻어야 진단을 선택할 수 있다. 올바른 진단 후 전원 분리, 전개부 고정, 래치 해제, 전원 복구, 작동 시험을 수행한다. 작동 시험의 완료 상태가 임무 성공과 보상의 근거다.

상태는 UI 버튼에만 의존하지 않고 `Mission` 내부에서도 검사한다. 저장 자료의 복원 때도 주요 선행 조건을 확인한다. 완료한 작업의 보상은 실행 ID로 중복 지급을 방지한다.

## 다음 개발의 우선순위

1. 실제 플레이 관찰을 바탕으로 접근 속도, 제동력, 포획 허용 범위와 카메라를 조정한다.
2. 통신 불가의 원인이 전원 연결 또는 안테나 구동부인 두 번째 임무를 추가한다.
3. 고장 정의를 원인·단서·작업·검증 조건의 데이터로 분리한다.
4. 예비품을 선택해 현장에서 교체하는 장비·적재 시스템을 추가한다.
5. 견인 임무와 정비소 작업 공간을 확장한다.

협동 플레이와 장거리 궤도 이동은 별도 개발 판단이 필요하다. 먼저 서로 다른 고장을 반복해서 고치는 재미를 검증한다.
